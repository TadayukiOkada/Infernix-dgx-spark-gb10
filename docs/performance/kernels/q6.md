# Linear kernels — Q6 (GB10)

Part of the [Linear kernel tables](README.md).

Measured 2026-11-02 at `f2a495e3c` (dev-rebased-20261028, 3 uncommitted file(s) (source edits: `bench/README.md`, `bench/ops/nvfp4_route_sweep.cu`, `docs/README.md`)) with `build-native/bench/infernix_linear_bench --qtype <qtype> --policy <policy> --n N --k K --sweep … --warmup 3 --repeat 12 --flush-mib 48` (cold-L2: the eviction buffer is read between samples; the default `exact` route set).

One row per token count `T`. `kernel` is the schedule the dispatch table in `src/ops/linear/q6/shapes/` selects at that `T`, with its dispatch band in parentheses: the shape file's own launch call, with its `using` aliases and `constexpr` constants substituted and literal ternaries folded where the result fits the cell (a parameterized alias such as `Simt<2>`, or one whose expansion is too long, stays as the source writes it). `TFLOP/s` = 2·N·K·T / median; `GB/s` = (weight + activation + output bytes) / median.

`%pipe` and `%mem` put each row against the envelope that governs it, so a shortfall is attributable rather than a gap to a single device number. `%pipe` divides by the measured MMA-pipe peak of the pipe that policy actually runs on (`a16` → BF16 HMMA 123.71 TFLOP/s); the packed weight format is not the ceiling — an A16 route dequantizes its stored weights and lands on the BF16 HMMA pipe whatever the codec. `%mem` divides by 240.6 GB/s, the `ckt env` measured read-only ceiling. A row is at its envelope when the percentage of the envelope that binds it — `mem` at decode widths, `pipe` at prefill widths — is near 100.

Two regimes keep both percentages far below 100 and no schedule closes them. First, a payload smaller than the bandwidth × memory-latency product (~295 KB here) cannot reach the read ceiling at all: the whole tensor must be in flight before the stream ends. Second, the timed window is the whole public Op, so a route that composes several launches pays every one of them.

Repeatability: each row is the better median of two independent cold-L2 passes. Across these 164 rows the passes differ by 0.3% (median), 2.04% (p90) and 11.74% (worst), so a single pass is not a repeatable number for the microsecond rows. Every pass ran with a quiet host: host-side memory work (a build, a `cuobjdump` of a large binary) shares GB10's LPDDR5X with the GPU and inflates measured kernel times.

Not covered: the `--routes fast` tiers (Q8 sliced-K, FP8 A8 pair, Q4 W4A8, NVFP4 A4 pair), the `invariant` policy, and route entries the benchmark never admits — the f16-accumulate route (`LinearRoutes::F16Accumulate`, `launch_f16`) and `launch_pair_block32`. A row with empty metrics is a policy band above the measured cap (`T > 2048`): production dispatch selects that schedule there, but the sweep did not time it.
